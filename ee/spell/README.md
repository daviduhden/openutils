# ee spell checker

`spell.c` and `spell.h` are ee's own affix-based spell checker, written in
C23. It is an original component: no third-party engine code and no
third-party dictionary data are included, and everything here is covered
by the project licence (see [`LICENSES/ee`](../../LICENSES/ee)).

## Scope

Supported, i.e. the subset ee needs:

- a dictionary given as a `.dic` word list with optional `/flags`;
- `.aff` directives: `SET`, `FLAG char|long`, `TRY`, `REP`, `PFX` and `SFX`;
- exact word lookup, one prefix or one suffix at a time;
- affix conditions: literals, `.`, `[...]`, `[^...]` and a trailing `*`;
- one-edit suggestions (replacement, deletion, transposition, substitution,
  insertion) driven by `TRY`.

Not supported (deliberately):

- two or more affixes on one word (cross product);
- compound words, `MAP` tables and n-gram suggestions;
- multiple dictionaries or languages;
- any encoding other than the byte-oriented data around `en_US`.

## Design

- Words are stored in a growable array and indexed by a chained hash table
  using FNV-1a.
- Affix conditions are parsed once into a token sequence and matched against
  the reconstructed stem.
- Suggestions are generated by single edits and validated with the same
  lookup path as a normal check.

The engine never executes a program, opens a socket or starts a thread. The
dictionary is read once, on the first query, and kept in memory.

## Dictionary files

ee does not ship a word list, because none that would be useful is available
under this project's licence. Use the `EE_DICTIONARY` environment variable,
or place `en_US.aff` and `en_US.dic` in one of the standard data directories
listed in [`ee(1)`](../ee.1).

The unit test [`tests/test-spell.c`](../tests/test-spell.c) exercises the
engine with the tiny dictionary in
[`tests/spell-test.aff`](../tests/spell-test.aff) and
[`tests/spell-test.dic`](../tests/spell-test.dic), which was written for the
test and carries the project licence.
